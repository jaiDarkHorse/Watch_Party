PHASE 12 — Drift correction

This is where your app starts feeling actually good.

Suppose:

Host     125.420 sec
Viewer A 125.380 sec
Viewer B 124.910 sec
Viewer C 126.020 sec

Every few seconds:

Host → SYNC

Server broadcasts:

{
  "position": 125.42,
  "serverTimestamp": 1786884123456
}

Viewer calculates expected position.

Then:

difference < 100ms
    ↓
do nothing


difference > threshold
    ↓
correct playback

Don't constantly set currentTime; that will make playback ugly.

But there's one very important Oracle configuration:

WebRTC/media servers use UDP, not just HTTP/HTTPS.

So your Oracle Cloud networking/security rules need to allow the required mediasoup RTP/RTCP UDP port range and TURN ports.

Don't deploy the SFU and only open port 443 expecting WebRTC to magically work.

🧠 One thing I'd change from your original architecture

Don't make the architecture:

Oracle
├── Signaling
└── SFU

as if those are two completely independent systems.

Make the overall design:

                         SYNCWATCH
                            │
             ┌──────────────┴──────────────┐
             │                             │
       APPLICATION SERVER              MEDIA SERVER
       Spring Boot                     Node.js
             │                             │
       ┌─────┼──────┐                mediasoup
       │     │      │                     │
      Auth  Room   Sync               Router
       │     │      │                /    |    \
       └─────┴──────┘               P1    P2    P3
             │                        │     │     │
             └──────── WebSocket ─────┘     │     │
                                            │     │
                                      WebRTC viewers

That's a much cleaner architecture for a serious portfolio project.

And since you're already building the SyncWatch frontend, don't throw that work away. Your current Milestone 1 frontend can become the presentation layer; now you build the Spring Boot + WebSocket + mediasoup infrastructure underneath it.

The next major step should be M1 → M2 → M3, then we attack the SFU. Don't start by trying to make the entire WebRTC system at once. That's how debugging turns into a 3 AM boss battle. 😄
